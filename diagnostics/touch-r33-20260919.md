# Superman r33 touch restoration — applied, hardware test pending

The user authorized applying touch restoration, explicitly excluding a full SD-card image build. This change supplies and explicitly loads the missing Synaptics RMI4 modules while retaining the r33 boot/kernel/DTB/ramdisk, quarantine and framebuffer path.

## Confirmed cause addressed

The captured r33 configuration has RMI4_CORE=m and RMI4_I2C=m, with F11/F12 and 2D sensor support. Android's product copied only the three power-key modules; init loaded only those modules. No module autoload path supplied RMI4. The deployed DTB, extracted from SHA256-verified r33 boot 3926ea3d..., already enables I2C3 (f9925000), touchscreen address 0x4b, IRQ GPIO17 falling edge, reset GPIO16 output-high, L15/L6 supplies, and F01/F11 nodes. No speculative GPIO/DT or controller-protocol change is applied.

## Applied files

- device.mk: install rmi_core.ko, rmi_i2c.ko and their provenance JSON.
- init.superman.rc: explicit core-before-I2C insmod commands after existing framebuffer relocation. Existing power-key loads and display operations retained.
- prebuilt/touch-r33/rmi_core.ko and rmi_i2c.ko: newly built ARM32 modules, stripped of debug sections only. Like existing kernel prebuilts, these are under the repository's ignored prebuilt directory; preserve the files and the evidence/build recipe when transferring this working tree.
- diagnostics/superman-touch-modules.json: module, boot and captured-config hashes, source commit, ABI and pending runtime status.
- diagnostics/superman-diag-capture.sh: add RMI module listing and a 16 KiB-capped /proc/bus/input/devices read to the existing 60-second snapshots. No event consumption, new worker, polling frequency, or sync call.
- diagnostics/superman-v70-build-manifest.txt: declare the applied touch load/capture scope, explicitly pending device test. No new built release identity is assigned.
- scripts/generate-build-manifest.py and package-quarantine-sd.py: bind the installed modules and provenance into generated/read-back component hashes; reject module hash drift or a different intended boot. Full packager was not run.

## Module provenance and independent ABI validation

The old generated kernel tree is not ABI-compatible with r33: its module_layout CRC is c683e053, versus runtime 71e4016d. It was not used to build modules. The driver source and headers come from the preserved pristine Mainline4Lumia commit b75aff58cd0646da93b98e0482f99b723ff0776c. A separate output directory .codex-restart/builds/r33-touch-modules-20260919 uses the captured current r33 /proc/config.gz and staged GCC 13.3.0 / binutils 2.42. It compiles only the RMI modules plus validation objects, not a replacement kernel executable or Android/system/SD image.

Olddefconfig changes only the compiler executable spelling, CC_CAN_LINK host probe result, and adds an explicit disabled DEBUG_INFO_SPLIT entry. The latter two stem from the staged toolchain, not feature changes; exact config diff is retained. No probe result was faked.

The preserved r33 zImage was decompressed and its 12,659 export names/CRCs recovered using the kernel linker-table format. The recovery procedure was cross-checked against all 12,390 exports of a separate preserved Image with its original vmlinux.symvers. recovered CRCs are reference build inputs, not patches to the kernel or module headers.

Crucially, all 84 distinct imported kernel symbols were also independently regenerated from the relevant pristine source exporter objects using the captured configuration and compared to the actual r33 kernel: all match, including module_layout. RMI inter-module exports, vermagic, ARM32 ELF headers, OF aliases, and dependency order were checked. Modversions enforcement is retained; no forced loading or CRC override was added to init.

## Validation and limits

Both modules compile without build warnings/errors. host_init_verifier and capture-shell syntax pass. A staging-only manifest test checks existing framework ZIP integrity and accepts the verified modules; missing/altered modules and a different boot are rejected without overwriting a prior valid manifest. Packager module paths agree with generator paths. Its image-level readback remains for the next authorized image build. Original r33 boot hash is unchanged.

Successful loading/probing, I2C communication, interrupts, coordinates, orientation and lock-screen swiping remain unverified until a device test. This is an applied restoration candidate, not a claim of working touch. Next capture should show rmi_core/rmi_i2c loaded, rmi4 physical input registered and Android EventHub/InputReader discovering it. If that fails, preserve init insmod errors and RMI/I2C probe logs before changing board resources. No USB, battery, media-extractor sandbox, GPU/MDSS or other functional fixes were included.

No Android system image or full SD image was built. No flash or removable-media write occurred. The existing built identity remains v70-graphicsdiag-r33-20260918.
